# 综合实践第 24P：摄像机跟随复盘

## 当前状态

- 第 24P“摄像机跟随逻辑”学习中。
- 已在 `GameScene1` 的 `_Cinematic_camera1` 上挂载并启用 `CameraMove`。
- 当前场景使用角色 2 作为跟随目标，偏移为 `(0, 6, -8)`，身体观察高度为 `5`，移动与旋转速度均为 `20`。
- 代码独立编译结果为 0 Error；仍需在 Play Mode 验证角色移动和转向时的实际跟随画面。

## 当前实现

- 以 `target.position` 作为跟随位置的基准。
- 使用 `target.forward * offsetXYZ.z` 计算角色朝向后方的距离，当前 Z 偏移为负数。
- 使用世界坐标上方向增加摄像机高度。
- 使用 `Vector3.Lerp` 平滑移动到目标点，使用 `Quaternion.Slerp` 平滑看向角色身体高度。
- 原摄像机 Animator 和 `CameraAnimator` 已在游戏场景禁用，避免动画继续覆盖运行时跟随结果。

## 本次排错

最初的空引用保护写成了 `target != null` 时返回。场景中的目标已经绑定，因此 `Update()` 每帧都会提前结束，移动和旋转逻辑完全没有执行。修正为只在 `target == null` 时返回后，跟随逻辑才能运行。

第二个问题是使用摄像机自身的 `transform.position` 加偏移计算目标点。这样每帧的目标点都会随着摄像机继续移动，摄像机会追逐一个不断变化的位置并持续漂移。现在改为从 `target.position` 开始计算，使目标点固定在角色周围。

## 当前边界

- 水平偏移仍使用世界坐标 `Vector3.right`。当前 X 偏移为 0，不影响效果；以后需要相对角色向左或向右偏移时，应改用 `target.right`。
- 当前脚本在 `Update()` 中执行。如果角色移动后出现轻微抖动，可在理解执行顺序后尝试改为 `LateUpdate()`，让摄像机在角色本帧移动完成后更新。
- 当前目标是场景内固定放置的角色 2。后续按玩家选择动态创建角色时，需要通过 `SetTarget()` 把实际玩家 Transform 交给摄像机。

## 最小验证

1. 进入 Play Mode，确认摄像机移动到角色后上方并看向角色身体位置。
2. 移动角色，确认摄像机持续跟随且不会不断漂移。
3. 旋转角色，确认摄像机后方位置随角色朝向变化。
4. 确认 Console 没有空引用或其他运行错误。

完成以上运行验证后，才能把第 24P 标记为“已完成”。
