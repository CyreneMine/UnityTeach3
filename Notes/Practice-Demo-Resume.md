## 可以深入讲的三个问题

### 1. 波次为什么会重叠

原先误以为调用带延迟的方法会等这一波怪物全部生成后才返回。实际调用会预约后续执行，当前调用继续向下走。修正后在本波最后一只怪物生成完成时才预约下一波，并区分待生成数、剩余波数与存活数。可用 [波次复盘](Practice-Monster-Logic-Review.md) 说明调试过程。

### 2. 为什么 UI 已隐藏却挡住按钮

透明度到达 0 后，用 `< 0` 判断结束导致隐藏回调无法进入，透明面板仍存在并拦截射线。修正结束条件后才能销毁面板并清理缓存。后来结算暂停又发现淡入依赖 `deltaTime`，改用 `unscaledDeltaTime` 让 UI 使用独立于游戏时间的帧间隔。可说明自己同时检查视觉状态、对象生命周期与输入行为。

### 3. 为什么炮头瞄一个目标却打中另一个

最初遍历选出了更近的 `_target`，攻击时却仍取碰撞数组第一项；瞄准点也曾只在更换目标时更新。修正为先选目标、每帧生成瞄准点，并让伤害使用同一个目标。另区分修改 Vector3 副本与修改真实 Transform，避免调整瞄准高度时移动怪物。见 [塔逻辑对照](Practice-Tower-Logic-Comparison.md)。

## 介绍时保持准确的边界

- 这是参考教程完成的个人练习，不能写成商业上线、团队项目负责人或全原创项目。
- 可以说“配置 7 个角色、16 条怪物数据、9 条塔数据”，不说“16 套独立 AI 行为”；怪物数据是模型与动画类别的组合。
- 可以说“JSON 配置管理与 Excel 数据转写”，不说“开发了通用自动导表框架”；当前批量转写由 Agent 协助，项目没有对应通用编辑器工具。
- 当前枪械使用射线判定，特效为反馈表现，不描述成完整弹道模拟。
- 项目脚本主要使用旧 `Input` API，工程启用 Both；不要写成全部基于新 Input System 的 Action 架构。
- 没有 Profiling、压测或对比数据，不添加帧率提升、并发数量、性能百分比等数字。
- 目前没有对象池、联网同步或 Alt/鼠标点击造塔的实现，不把设想写进已完成成果。
